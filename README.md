# 图谱 / Atlas

一套规范 + 一个工具 + 一个画布，用来管理所有按这套规范做的项目。

解决的是同一个问题：**AI 产出太快，东西到处都是，没人知道该从哪进、谁是谁。**

## 三句话说清它怎么工作

1. 每个 md 开头写两行 frontmatter（`类型`、`状态`），AI 顺手就写了。
2. 每个项目手写 5~10 条**路线**，说清楚"做一件事走哪几步"。
3. 其余全部由程序扫描生成：索引、校验、画布。

源数据只有这两处，生成物随时可以删掉重建。

## 为什么不是又一个 Obsidian

Obsidian 画的是**引用图**——谁引用了谁，多对多，必然是毛线球。你真正需要的是另外两张：

- **分类图**（这是什么、归谁管）→ 是属性，不是线，程序扫出来
- **路线图**（做一件事走哪几步）→ 稀疏，十几个节点，**必须手写，算不出来**

Atlas 只画后两张，引用图降级成搜索和卡片内的列表。

## 目录

```
Atlas/
  规范/
    元数据规范.md    frontmatter 写什么、不写什么
    目录规范.md      项目长什么样，七个顶层目录各管什么
    路线规范.md      路线怎么写，为什么必须手写
    视图规范.md      画布怎么画才不变成毛线球
    词表.yml         机器读的唯一来源，文档从它生成
  模板/
    游戏项目/        脚手架，一条命令生成整套骨架
    通用项目/
  atlas/             CLI：扫描、校验、生成、批量迁移、本地服务
  视图/              画布
  路线/              Atlas 自己的生产路线
  注册表.yml         管着哪些项目，各自根目录在哪
```

## 每个被管理的项目

```
<项目>/
  项目.yml    身份：名字、主分组维度、内容类型词表、编号前缀
  AGENTS.md   导航协议，20 行以内
  路线/ 策划/ 内容/ 创意/ 资产/ 产出/ 工具/
```

`策划` 是规则层（该怎么做），`内容` 是实例层（做出来的东西），`产出` 是 AI 的倾倒区，`资产` 是从产出里挑中认领的。详见 [目录规范](规范/目录规范.md)。
