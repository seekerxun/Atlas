# 目录规范

```
<项目>/
  项目.yml           项目身份：名字、主分组维度、内容类型词表
  AGENTS.md          导航协议，20 行以内
  路线/              生产流程，手写，5~10 条
  策划/              规则层：世界观 系统 数值 机制 规范
  内容/              实例层：实体 md + 数据表
  创意/              未立项，零门槛
  资产/              已认领的产出，按实体编号组织
  产出/              AI 的倾倒区，默认不扫描
  工具/              脚本与工作台
  .atlas/            生成物：索引、布局、地图
```

**不用数字前缀。** `01-世界观` 那种前缀是为了在文件树里排序，有了画布就不需要了，而且会让改名和搬动变麻烦。

---

## 路线

生产流程，是唯一"算不出来、必须手写"的东西，也是唯一能回答"我现在该干什么"的东西。其余四个库都被它串起来。格式见 [路线规范](路线规范.md)。

## 策划

规则层：定义"副本该怎么设计"、"数值怎么算"、"有哪些机制"。跨实例、数量稳定（几十篇封顶）、每条规则只有一个权威文档。

按域分子目录：`策划/世界观/`、`策划/系统/`、`策划/数值/`、`策划/机制/`、`策划/规范/`。

## 内容

实例层，随项目无限增长，**按项目的主分组维度分目录**：

```
内容/
  _公共/              跨分组的实体
  _待定/              还没决定归哪个分组的实体，定了再搬
  _模板/              各类型的字段模板
  W-001-断武之境/      ← 主分组维度 = 世界
    世界.md           这个分组的根节点
    NPC/ 势力/ 副本/ 剧情/ 道具/
  表/                 CSV 数据表 + 同名说明 md
```

主分组维度在 `项目.yml` 里声明，游戏项目填 `世界`，别的项目可能填 `模块`、`客户`、`版本`。

为什么内容按分组优先、不按类型优先：做一个世界是一次完整的工作，文件集中在一处，AI 的上下文天然被圈住；一个分组可以整体新增、搁置、砍掉，不会在八个目录里留下碎片。**类型那一维不会丢**——写在 frontmatter 里，画布照样能按类型聚合。目录留给日常导航，另一维交给程序。

## 创意

零门槛。只要一行 `类型: 创意`，不校验、不判孤儿、不进导航主图。门槛一高你就不往里丢了，那它就废了。

立项 = 搬进策划或内容并补齐 frontmatter。**这一步是人做的决定，不是 AI 做的。**

## 资产 与 产出

这两个必须分开，它们是"混乱的隔离带"：

```
产出/     AI 刚生成的一切：图、试算表、文案草稿
         按 批次-日期 分目录，允许乱，默认不扫描不校验
资产/     被挑中、被认领的，按实体编号组织
         资产/W-001-断武之境/NPC-W001-001/立绘-v3.png
```

流程：**生成 → 落进产出 → 挑一张 → 认领到某个实体 → 其余归档或删。**

- AI 不知道东西放哪，一律丢 `产出/`。给它一个指定倾倒区，它就不会再往 `策划/子目录/子目录` 里塞东西。
- 迭代版本的混乱（v1、v1.4.6 那一堆）本质是"缺一个挑中动作"。加上认领步骤，混乱就被关在 `产出/` 里，`资产/` 永远只有定稿。
- 生成参数、prompt、来源记录属于**生产记录**，跟着批次留在 `产出/`，不要混进 `资产/`。

资产目录名带实体编号，程序靠它自动把图挂回条目；挂不上的进画布的「未认领」抽屉。

`资产/` 里也可以放**单文件网页**（`.html`，如打包好的交互页）：它是成品，按资产处理，不算工具；在别处的 `.html` 仍按工具处理。

## 工具

脚本、工作台、生成器。**工具不建注册表，谁用谁在文档的 `工具:` 里声明。**没有任何文档声明的工具就是孤儿工具，会被报出来——这直接治"AI 把脚本藏在子目录的子目录里"。

工具只放 `工具/`，放在别处会报"放错位置"。

## 代码目录

工具项目的源码、游戏项目的引擎工程，是**产品本身**，不是"工具"。在 `项目.yml` 里声明：

```yaml
代码目录: [atlas, 视图]
```

声明过的目录不判孤儿工具、不判放错位置。Atlas 自己就是这么过的自检——
不加这条，它自己的源码会被自己报成八个"脚本放错位置"。

里面的 md 也按产品文件处理，和 `AGENTS.md` 一样豁免：不要求 frontmatter、不校验字段、不判孤儿。
框架自带的说明文件（比如视频工程里的 `BRIEF.md`、`CLAUDE.md`）因此不用为了过检查去改格式。
它们照样进索引，路线的 `docs` 可以引用。

## .atlas/

索引、布局、生成的地图。**进 .gitignore，随时可以删掉重建。**

---

## 编号

文件名 = 编号 + 空格 + 名称：`NPC-W001-001 灰烬修女.md`。编号不写进 frontmatter。

前缀词表由项目在 `项目.yml` 里定。分组专属的带分组码（`NPC-W001-001`），跨分组的不带（`SKL-003`）。

资产目录用同样的编号命名，程序靠它自动挂接。

---

## 给 AI 的规矩只有两条

1. 新建 md 带两行 frontmatter：`类型`、`状态`。
2. 不知道放哪，就丢 `产出/`。

其余全部靠程序在提交前检查。规矩超过三条，AI 就会挑着执行。
