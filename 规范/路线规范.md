# 路线规范

## 为什么路线必须手写

一个项目里有三张图，你以前把它们混成了一张，所以怎么调都看不清：

| 图 | 形态 | 怎么办 |
|---|---|---|
| 引用图（谁引用了谁） | 多对多，必然是毛线球 | **不看**，降级成搜索和卡片内的列表 |
| 分类图（这是什么、归谁管） | 是属性，不是线 | 程序扫 frontmatter，自动出 |
| **路线图**（做一件事走哪几步） | 稀疏 DAG，十几个节点 | **手写**，这才是卡片链 |

路线**算不出来**。引用关系里生成不出"先干嘛后干嘛"。但正因为手写，它永远是干净的，而且只要写 5~10 条，写完基本不动。

## 格式

```yaml
route: 出一个NPC
desc: 从设定到可进原型
entry: false          # 标 true 的在地图首页置顶

steps:
  - id: 读规则
    title: 吃规则
    note: 只读这三篇。机制名一律去机制目录查，不要自创
    docs:
      - 策划/系统/角色系统
      - 策划/数值/角色属性
      - 策划/机制/机制目录
    next: [写条目]

  - id: 写条目
    title: 写 NPC 条目
    docs: [内容/_模板/NPC]
    tools: [工具/numeric-workbench]
    outputs: ["内容/W-*/NPC/*.md"]
```

| 字段 | 说明 |
|---|---|
| `id` `title` | 必填 |
| `docs` | 文件路径，不带 `.md`。不存在会报错 |
| `tools` | 这一步要用的工具 |
| `outputs` | 这一步产出到哪（glob） |
| `next` | 后续步骤，**画布上的线就是它** |
| `note` | 一句话提示，显示在卡片上，专门用来约束 AI |

位置坐标**不写进 yml**，存 `.atlas/布局.json`。yml 始终保持十几行、人能读、git 能 diff。

## 它怎么治上下文爆炸

把 `AGENTS.md` 从"知识载体"改成"导航协议"，20 行以内。AI 进项目读 20 行，然后：

```bash
atlas 路线 出一个NPC
```

拿到的是一份七八个文件的清单，不是两百个 md：

```
## 步骤 1 — 吃规则
#  只读这三篇。机制名一律去机制目录查
读  策划/系统/角色系统            # 系统 · 86行
读  策划/数值/角色属性            # 数值 · 120行
读  策划/机制/机制目录            # 机制 · 210行
...
共 7 个文件 / 约 500 行。只读这些，不要额外浏览目录。
```

`note` 字段是专门给 AI 的护栏，写"别翻 XX 目录"这种话，它会跟着清单一起输出。

## 写路线的三条经验

1. **先写你最常干的那件事**，跑一次看清单对不对，再写第二条。
2. **入口步骤只写一次。** 所有路线共用的"进项目必读"抽成公共入口，不要每条路线抄一遍。
3. **路线是你的，AI 不许改。** 它可以建议，改由你来。路线一旦被 AI 自动维护，就会退化成引用图。

## 没有对应路线的时候

用 `atlas 找 <关键词>`，不要 grep 全仓。找不到就说明这件事值得加一条路线，或者那个东西压根不该存在。
