# Atlas 桌面打包

## 结论

当前最合适的是：**保留 Python 后端，用本机 Google Chrome 的 App 窗口显示页面，再用 PyInstaller 打包 Python。**

已经实现此路线。它没有引入 WebUI、Rust、Go、Node 或 Chromium。用户机器需要安装 Google Chrome，但不需要安装 Python。开发时仍保持标准库零依赖，只有制作发布包需要 PyInstaller。

这是一版可运行的桌面封装原型，尚非完成双平台验收的正式安装包。macOS arm64 已实际构建、启动和验证；Windows 提供可执行构建脚本，但尚未在 Windows 实机验证，已有平台限制见下文。

## 代码核查

| 项目 | 实际情况 |
|---|---|
| package.json、npm 构建 | 没有；也没有 Vite、Webpack、React、Electron 工程 |
| CLI | `atlas/atlas.py`，Python 标准库程序 |
| 后端 | `atlas/serve.py`，ThreadingHTTPServer，绑定 127.0.0.1 |
| 业务代码 | model、scan、lint、edit、rename、projects、targets、disk_usage 等 Python 模块；YAML 用自带 miniyaml 解析 |
| 前端 | `视图/画布.html`、`核心.js`、`主题加载器.js`、CSS，浏览器直接加载 ES modules，无编译步骤 |
| 接口 | `/数据`、`/文件/`、`/预览/`、`/布局`、`/路线`、`/还原`、`/打开项目`、`/新建项目`、`/运行` 等；大量同源绝对路径 fetch |
| 静态资源 | 六套主题；核查时视图约 5.6 MiB，幻想主题约 4.9 MiB，主要是 WebP；SVG/CSS/JS 均本地提供 |
| 外部资源 | 核查页面、主题和加载器未发现外部 CDN 库或远程字体依赖；用户管理的 HTML/媒体本身另计 |
| 数据 | 各项目 `项目.yml`、文档、路线、资产；布局与审阅等写各项目 `.atlas/`；主题及搜索偏好写 Chrome localStorage |
| 当前开发启动 | `.devdock.json` 指定本机 Homebrew Python 和本机绝对路径，服务端口 7392；CLI 默认端口 7391 |

项目原有代码并不是完全跨平台：运行目标管理用了 `/usr/sbin/lsof`、`os.getuid()`，磁盘统计用了 `st_blocks`；换 GUI 框架不会替换这些代码。

## 方案对比

| 维度 | 本次：Python + Chrome | WebUI + 原生后端 | Tauri 2 |
|---|---|---|---|
| 强制本机 Google Chrome | 是；找不到直接提示，不回退 | 可指定 Chrome；需检查打开失败 | 标准 WebView 路线不满足 |
| 内置 Chromium | 否 | 否 | 否，但 Windows 需要 WebView2 |
| 复用现有后端 | 直接复用 | 保留 Python 则仍需携带 Python；改 Go/Rust/C 则要迁移业务 | 可携带冻结的 Python sidecar，或重写 Rust 后端 |
| 前端改动 | 无需重写 fetch | 只打开现有服务可以复用；改用 WebUI bridge 则要接入桥接、事件、文件服务及生命周期 | 直接加载后端本地 URL 可复用；改成本地静态资源则需处理请求 origin、接口地址与权限 |
| 包体 | 本机完整 .app 约 26 MiB，含全部主题和 Python | 仅宿主库很小不等于整个 Atlas 小；保留 Python 并无直接体积收益 | 保留 Python 时仍要携带它；不能套用纯 Tauri 空壳大小估计 |
| 原生菜单、Dock、窗口管理 | Chrome 管窗口，集成有限 | 浏览器模式也受 Chrome 窗口约束 | 更适合完整原生窗口、菜单、托盘与安装分发 |
| 当前适配成本 | 最低，已验证 | 用作壳增加依赖；彻底替代 Python 是后端迁移项目 | sidecar/启动/退出、资源与权限、WebKit 验证均需实施 |

WebUI 官方 API 有 `webui_show_browser(window, content, Chrome)`，支持打开 URL，也提供 Python 包装器，不必为了采用 WebUI 而先重写 Go。WebUI 的桥接通常使用 `webui.js` 与 WebSocket；Atlas 已经有 HTTP API，因此现在增加第二套桥接的收益有限。

Tauri 在 Windows 使用 Edge WebView2，在 macOS 使用 WKWebView。它不等于调用已安装的 Google Chrome。当前未发现 Atlas 必须依赖 Chrome 独占 API 的证据，所以不能断言它在 WebKit 上不能运行；但用户偏好的“统一使用本机 Chrome”与 Tauri 默认架构不符。

若未来要求更小的**独立分发包**，可以评估 WebUI + Go/Rust/C，并迁移扫描、元数据解析、mtime 冲突保护、撤销恢复、项目管理、运行目标和文件服务。只加一层 Go/Rust 启动器而仍打包 Python，不会消除 Python 的体积。若允许用户自行安装 Python，源码启动方式更小，但不属于开箱即用的分发方案。

## 已实现的配置

- `atlas/desktop.py`：Google Chrome 查找、专用持久 profile、单实例锁、用户数据目录、多项目服务宿主、诊断入口及错误日志。
- `atlas/build_desktop.py`：Windows/macOS 共用的 PyInstaller 构建脚本；按白名单携带视图、模板与词表。
- `model.py`：冻结后从应用包资源目录读取资源。
- `projects.py`：桌面注册表独立存放；冻结后派生服务使用自身 `--cli`，不调用构建机器的 Python；生成模板内 CLI 指令也相应替换。
- `serve.py`：每个服务使用独立的处理器状态，支持一个进程管理多个项目；关闭时释放监听端口。
- `targets.py`：避免 Windows 因缺少 getuid 而直接崩溃，修正绝对路径判断；缺少 lsof 时明确报告功能暂不支持。
- 桌面自建服务限制 Host/Origin 为本机同源。已有外部服务复用后仍使用它原来的请求策略。

用户数据默认位置：

- macOS：`~/Library/Application Support/Atlas/`
- Windows：`%LOCALAPPDATA%\Atlas\`
- 可用 `ATLAS_STATE_DIR` 改写，用于测试或自选数据目录。

注册表、ChromeProfile、日志和上次打开项目记录放在这里。首次没有指定项目时，在此建立“我的项目”；可以通过页面打开现有项目或在自选位置新建项目。真实文档与布局仍写到各项目原目录，不写入 .app。不会自动导入源码根目录的私人注册表；通过页面打开原有项目即可重新登记。

包中不包含本机 `注册表.yml`、`.devdock.json`、`.atlas/`、Git、产出或其他受管理项目。已存在项目的旧运行目标命令不会被自动改写，移机后应按目标机器检查它们的可执行路径。

## 开发与构建命令

以下从 Atlas 仓库根目录执行。不要执行 `npm install` 或 `npm run build`，此项目没有对应工程。

源码运行（Python 3.10+；此次构建使用 Python 3.13.15）：

```sh
python3 atlas/atlas.py serve --port 7392 --no-browser
```

桌面模式运行，强制本机 Chrome：

```sh
python3 atlas/desktop.py --project "/Users/seekerxun/Documents/LifeSpace/Atlas"
```

macOS 打包：

```sh
cd "/Users/seekerxun/Documents/LifeSpace/Atlas"
python3 -m venv .atlas/build-env
.atlas/build-env/bin/python -m pip install "pyinstaller==6.22.0"
.atlas/build-env/bin/python atlas/build_desktop.py
open "产出/桌面版/Atlas.app"
```

如已有 uv，可用 `uv venv --python 3.13 .atlas/build-env` 创建环境，再用 `uv pip install --python .atlas/build-env/bin/python 'pyinstaller==6.22.0'` 安装构建依赖。发布包架构跟随构建 Python，此次是 arm64；Intel 版本须使用对应的 x86_64 构建环境并测试。

Windows PowerShell 打包（仓库放到你实际的 Windows 路径，例如 `C:\src\Atlas`）：

```powershell
Set-Location C:\src\Atlas
py -3.13 -m venv .atlas\build-env
& .\.atlas\build-env\Scripts\python.exe -m pip install "pyinstaller==6.22.0"
& .\.atlas\build-env\Scripts\python.exe atlas\build_desktop.py
& '.\产出\桌面版\Atlas\Atlas.exe'
Compress-Archive -Path '.\产出\桌面版\Atlas' -DestinationPath '.\产出\Atlas-Windows.zip'
```

Windows 采用 onedir，必须分发整个 Atlas 文件夹，不能只复制 EXE。PyInstaller 不是跨系统编译器，不能把本机 macOS 构建直接当成 Windows 包。以上 Windows 命令尚未实机执行。

诊断与测试：

```sh
python3 atlas/desktop.py --diagnose
python3 -m unittest discover -s atlas -p 'test_*.py'
node atlas/test_search.js
node atlas/test_disk_usage.js
python3 atlas/atlas.py check
```

Node 只用于已有 JavaScript 回归测试，应用运行不需要 Node。

已有 .app 可用 `Atlas.app/Contents/MacOS/Atlas --diagnose` 查看冻结资源与 Chrome 路径；用 `--project "项目路径"` 指定项目；`--no-browser` 用于只开服务的验收。`ATLAS_CHROME` 可显式指定非标准安装位置的 Google Chrome 可执行文件，该覆盖值由调用者负责保证是 Chrome。

此实现采用 onedir；没有采用 onefile 的启动时临时解包方式，避免把临时解压资源当成可写持久数据。

## 验证结果与未完成事项

2026-10-11，本机 macOS arm64：

- 使用 Python 3.13.15、PyInstaller 6.22.0 完成 .app 构建；资源诊断确认 frozen=true、内置模板和 HTML 均存在。
- 完整 .app 实测约 26 MiB；此数字不含已安装 Chrome、运行后产生的 Chrome profile/cache，也不代表运行内存。
- 冻结应用 HTTP 验收：49 个 HTML/JS/CSS/JSON/SVG/WebP 文件与源码逐个比对通过，布局保存、新建第二个项目及项目隔离通过。
- Chrome 实际显示打包后的页面与幻想主题，页面浏览器日志未发现 error/warn；独立 Chrome 进程使用指定 `--app` 与专用 profile 启动。
- Python 回归共 10 项通过；现有搜索、搜索历史及磁盘请求 JavaScript 回归通过；`atlas check` 零错误、零警告。
- 验收使用临时目录中的示例项目，没有拿用户业务文档做写回测试。

剩余边界：

1. **Windows 尚未完整适配和验收。** 运行目标的按端口进程归属检查与停止依赖 lsof，当前返回明确错误。需要 Windows 进程枚举/归属检查实现，不能用“直接杀端口进程”替代安全边界。
2. **Windows 实际磁盘占用尚未支持。** 现有统计依赖 st_blocks；没有该字段时明确提示失败，不冒充逻辑字节数。需要单独实现并验证 Windows 分配空间口径。
3. **Chrome App 模式仍是 Chrome 窗口。** Dock、菜单、任务切换、多项目弹窗不保证像完整原生 App；`window.open` 的新项目可能出现普通浏览器窗口。macOS 关闭最后一个窗口未必退出 Chrome 进程，宿主以专用 Chrome 进程退出为生命周期边界；因此不能承诺点关闭按钮立即结束全部服务。只关闭本宿主创建的画布服务，不关闭此前由 DevDock 启动的服务，也不自动停止用户的外部运行目标。
4. **分发工作尚未完成。** 当前只有本机开发用途的 ad-hoc 签名，没有 Developer ID 公证、Windows 签名/安装器、自动更新、定制应用图标或 universal2 包。正式发布前需要独立做这些流程；不要把当前产物宣传成已签名公证的商用安装包。
5. 冻结 CLI 保留供服务和常用导航调用；原有 `hook` 按源码脚本路径生成 Git 钩子，冻结入口会明确拒绝该命令，需要钩子时使用源码 CLI。移动应用后新项目中记录的绝对 CLI 路径也需重新配置。
6. 自建桌面服务增加了同源检查，但这不等于对所有原有 HTTP 接口、用户 HTML 预览和本机恶意程序做过完整安全审计。当前定位为可信本机项目工具。
