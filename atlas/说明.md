# atlas 工具

已经能跑。入口 `atlas/atlas.py`，零依赖，Python 3 直接执行。
项目里放一个 `工具/atlas` 转发脚本，之后就是 `./工具/atlas 检查`。

所有命令都已实现，包括 `atlas serve`（本地画布）。

## 三条不能妥协的约束

1. **零安装依赖。** 不能因为 `pip install` 少了个包就跑不起来——AI 一报错就会退回去 grep 全仓，整套设计立刻失效。frontmatter 只用严格子集，自己解析，不依赖 PyYAML。
2. **全仓扫描。** 不是只扫 `工具/` 和 `资产/`。藏在 `策划/临时/草稿/` 里的脚本和图必须被发现并报"放错位置"——那正是这套东西要解决的核心问题。
3. **写回只碰 frontmatter。** 画布和迁移命令都只改 frontmatter 区块里的指定字段，不碰正文；写之前比对文件修改时间，不一致就中止。

## 命令

| 命令 | 作用 |
|---|---|
| `atlas 新建 <模板> <路径> [--名称 显示名]` | 从 `模板/`（目前只有通用项目）生成项目骨架，替换名称和 atlas 路径，写 `.devdock.json`（分配端口），登记进注册表；画布的「新建项目」走同一套代码 |
| `atlas 扫描` | 写出 `.atlas/索引.json` |
| `atlas 检查` | 体检，有错误退出码 1（给 pre-commit 用） |
| `atlas 路线 --列表` | 列出所有路线 |
| `atlas 路线 <名字>` | **给 AI 用**：输出这条路线的文件清单和总行数 |
| `atlas 找 <关键词>` | 搜条目/工具/资产，并说明工具的服务对象；`代码目录` 里的文件标成「代码」，与检查的 W02 判定一致，不报孤儿 |
| `atlas 迁移 --加字段 / --改名 / --演习` | 批量改 frontmatter |
| `atlas 认领 <文件> <条目>` | 把资产或工具挂到某个条目上 |
| `atlas 改名 --类型/--条目/--词表/--字段` | 改名并算出全部影响面（目前只预演） |
| `atlas serve` | 起本地画布（只绑 127.0.0.1），只管当前项目。画布里打开别的项目，会在那个项目 `.devdock.json` 写定的端口上另起服务 |
| `atlas 运行 [目标] [--停止]` | 列出当前项目 `.devdock.json` 里的运行目标及状态；带目标名就启动或停止它。规则与 DevDock 相同，画布顶栏的运行面板走同一套代码 |
| `atlas 钩子` | 安装 git pre-commit |

每个命令和选项都有英文别名，与中文等价、可混用，例如 `atlas check`、`atlas route --list`、`atlas serve --port 7391 --no-browser`；完整对照见 `atlas -h`。

新建项目只继承模板的内容和权限，不复制模板时间戳；新文件和目录使用实际生成时间，避免 macOS 把创建日期回退到模板的旧日期。目标若是已有的空目录，则保留它原本的创建日期。

工具要能在项目任意子目录下跑，自动往上找 `项目.yml`。

## 本机项目注册表

根目录的 `注册表.yml` 存放本机项目路径，加入 `.gitignore`，不提交 Git。
首次新建或打开项目时会自动创建；需要手动配置时，复制根目录的
`注册表.example.yml` 为 `注册表.yml`，按示例填写本机绝对路径。
换电脑后重新登记项目，不沿用其他电脑的路径。

## 扫描要做的事

1. 走全仓，按 `项目.yml` 的忽略列表跳过
2. 解析每个 md 的 frontmatter，按目录推导 `库` 和 `分组`
3. 把所有文件按规则归类：文档 / 工具 / 资产 / 表 / **未归类**
4. 建反向关系（谁引用了我、我出现在哪些路线里）
5. 资产目录名按编号正则自动挂回条目
6. 正文里的 `[[双链]]` 抽成软引用（不画线，只在卡片里列出）
7. 写 `.atlas/索引.json`

## 校验规则

见 [词表.yml](../规范/词表.yml) 的 `校验` 段。要点：

- **E05 机制名校验**：`机制:` 的值必须是项目 `机制权威` 文档里的标题。这条把"同一个概念全库同一个名字"变成程序执行。
- **W02 孤儿工具 / W04 放错位置 / W05 未归类文件**：这三条是"AI 到处乱丢东西"的直接证据，优先看它们。
- 体检结果不要只给一个总分。**分数会骗人**——一个故意做乱的样例项目也能拿 77 分。直接报三个数：未归类文件数、孤儿工具数、缺 frontmatter 数。

| `atlas.py` | CLI |
| `serve.py` | 本地画布服务：/数据、/候选、/文件、/布局、/认领、/路线、/删路线、/项目、/打开项目、/新建项目、/运行 |
| `targets.py` | 运行目标：读 `.devdock.json`，查状态、启动、停止；状态与停止规则照 DevDock，端口上的进程工作目录不在项目里就拒绝停止 |

## 真实数据撞出来的五个细节

用无常乐园头两批文件验规范时发现的，写代码时别踩：

1. **豁免文件仍然可以被路线引用。** `AGENTS.md` 不要求 frontmatter、不算条目，但路线的 `docs` 里写 `AGENTS` 是合法的。校验时按"文件存在"判断，不要按"是不是条目"判断。
2. **机制名从表格首列读，不要从标题读。** 机制权威文档里混着"通用判定""机制索引"这类分节标题，按标题抽会把它们当成合法机制名，E05 就成了假校验。项目在 `项目.yml` 里用 `机制名来源: {段落, 取法}` 声明从哪取。
3. **列表值要按逗号切，不要用正则 findall。** `机制: [A, B, C]` 用 `[\[,]...[\],]` 这类正则匹配会吃掉分隔符导致跳项——B 会被静默漏掉。这类 bug 的后果是**校验假装通过**，比报错危险得多。
4. **YAML 写法必须收紧成一种，这是假校验的最大来源。** 同一个 `资产:` 字段，行内列表能校验、`-` 多行列表悄悄跳过，结果是"改成不存在的图也不报错"。规范已经收紧成"列表一律行内、嵌套最多一层"，解析器遇到别的写法**直接报 E10，不要宽容处理**。三次假校验全出自这一类，写代码时优先保证：**宁可误报，不可漏报。**
5. **分组未定的条目要有地方放。** 灰烬修女属于哪个世界还没定，既不是公共内容也不属于任何世界。约定放 `内容/_待定/`，定了再搬。`_待定/` 不判孤儿，但在画布上单列一块，提醒你还欠着决定。

## 画布

`/数据` 同时返回 `搜索正文`（扫描纳入的文档路径 → 去掉 frontmatter 的完整正文）和 `搜索遗漏`（正文读取失败的路径）。搜索正文仅用于画布，不写入磁盘索引；遵守项目扫描范围并拒绝读取项目外的链接目标。每次重新扫描更新，不能读取的正文由界面明确提醒。

见 [视图规范](../规范/视图规范.md)。第一版已经能用：

- 五个视图（路线 / 策划 / 内容 / 创意 / 资产），按 `1`-`5` 切
- 无限画布，滚轮缩放、空白处拖拽平移
- **容器从数据来**：内容库按分组分盒，盒内按类型分组，不需要维护布局
- **语义缩放**：远景只剩容器名（字号反向补偿缩放保持可读），卡片退成色块；
  中景显示名字和摘要；近景加状态、被引数、缩略图
- 关联高亮和跳转保留；现有主题只绘制路线流程线，普通引用不画连线
- 卡内展开：点击卡片放大，在卡内阅读正文、属性、调用机制、关联（可点跳转）、被谁引用和缩略图；Esc 或「收起」返回画布
- 左下「未认领」抽屉：未认领资产、孤儿工具、未归类文件。
  **拖一项到卡片上就写进那篇 md 的 frontmatter**
- 同一个抽屉底部列产出池：`产出/` 下一个目录算一批，显示件数和距最近修改的天数；
  超过 14 天的批次归到「该清了」。产出池不算未认领件数、不进 `atlas check`，也不能直接拖去认领
- 拖动卡片和容器存 `.atlas/布局.json`，不进 yml

**路线图可以直接编辑**，基本不用手开 yml：

| 操作 | 怎么做 |
|---|---|
| 连线 | 从卡片右侧圆点拖到另一张卡 |
| 断线 | 点那条线 |
| 加一步 | 路线标题下「+ 加一步」 |
| 删一步 | 展开卡片最下面「删掉这一步」（卡片上不放删除，太容易误点） |
| 改标题、护栏 | 展开卡片里点一下 |
| 挂文档 | 展开卡片「＋ 挂一篇文档」，弹出可搜索的候选列表 |
| 加工具、产出 | 展开卡片里加 |
| 新建 / 删除整条路线 | 顶栏「＋ 新路线」/ 路线标题下的删除按钮 |

**连线会挡住成环**：路线必须是有向无环图，连成环直接拒绝并提示。

界面文件职责及主题接口见 [视图说明](../视图/说明.md)。

## 撤销 / 重做

`⌘Z` 撤销、`⇧⌘Z` 重做（右下角也有按钮，鼠标悬停显示这一步是什么）。
连线、断线、增删步骤、改标题护栏、挂文档、认领资产、新建删除路线、拖卡片位置，全都能撤。

**做法是文件全文快照，不是给每种操作写逆操作。**每个会写盘的接口都返回「改之前的全文」，
画布把它压进栈；撤销就是把那份全文写回 `/还原`。好处有三个：

1. 新增一种编辑操作不用再写一遍逆操作，白捡撤销能力
2. 撤销结果和原文**逐字节一致**——按模板重新序列化会留下引号、空行之类的痕迹，快照不会
3. 撤销和重做是同一条代码路径，只是写回的内容不同

**冲突保护**：每一笔记着写完时的 mtime，撤销前比对。对不上说明 AI 或你在别处动过这个文件，
直接中止并提示，绝不覆盖。实测：撤销后在外部往文件里追加一行，再按重做，服务端拒绝、栈不动、
文件没被碰。

## 改名

"改一个名称，所有 md 全部搞一遍，总有东西改不到"——这是这套东西要治的核心病。

在代码里改名便宜，是因为**引用里不含名字**：改一处声明，其余是符号引用。
文档要拿到同样的性质，就得照搬：**编号是常量，名字只是显示值。**

四种改名共用一个引擎，差别只在影响面包含哪几类：

| 种类 | 影响面 |
|---|---|
| `--条目 PWR-003=内功武道` | 文件名、别人 `关联:` 里的显示名、正文 `[[双链]]`、路线 `docs`、资产路径里的编号 |
| `--类型 副本=世界节点` | frontmatter 的 `类型:`、`项目.yml` 词表与编号前缀、目录名、模板文件、路线引用 |
| `--词表 机制:旧=新` | 名单那一行、frontmatter 的引用字段、正文锚点链接 `[[…#名字\|名字]]` |
| `--字段 旧=新` | 全库 frontmatter 的键 |

两条铁律：

1. **正文里的自然语言提及只列不改。**"这个副本很难"里的"副本"可能说的是别的。
   工具列出位置和那一行，你自己判断——但至少你知道它们在哪，不会漏。
2. **仓库外的消费者只列不改。**声明了 `代码目录` 就在那儿搜一遍列出来，明确说"这些我不碰"。

**Atlas 核心字段（`资产` `机制` `关联` …）不让改**，直接拒绝并说明理由：
改它要动 `model.py`、`lint.py`、画布，那是改代码不是改数据。要扩往 `扩展:` 里加。

## 写回的安全边界

两条写回路径都走 `edit.py`：

- **frontmatter**（`/认领`、`迁移`）：每次写回前重新读文件，只替换 frontmatter 区块，
  正文原样保留。
- **路线 yml**（`/路线`）：**按固定模板整篇重写，不做 YAML 往返**——往返会丢注释、打乱顺序。
  文件开头的注释会保留。往返测试过：解析→序列化→再解析，结构完全一致。

两者写回前都比对修改时间：画布拿到数据时记下 mtime，写回时对不上就报错中止。
实测拿一个过期 mtime 去写，服务端拒绝且文件没被动。所以画布上的操作不会覆盖
AI 同时做的修改，最坏是报错让你刷新。

## 这套东西真正的失败模式

不是设计不好，是**没人写 frontmatter**。所以 `atlas 钩子` 比上面所有功能加起来都重要——缺 frontmatter 直接挡住提交。
